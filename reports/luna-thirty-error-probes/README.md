# Последующий разбор Luna30

Эти файлы не входят в исходный эксперимент и не меняют 12/30 и 17/30 совпадений ответов Луны с эталоном.

- `source-excerpts.json` — полные исходные записи 13 задач, включая закрытые при прогоне поля `nl2fol`, `reasoning`, `answer`, `conclusion_fol`. Перед выделением записей проверен SHA-256 полного датасета. Эти поля изучены только при последующем аудите.
- `results.json` — 41 запуск SWI-Prolog. Каждый запуск получает полный кандидат в свежем процессе с ограничением 10 секунд. Здесь нет новых ответов модели.
- `case-ID-baseline.pl` — неизменённая формализация модели плюс директива загрузки решателя. Отдельный `-query.txt` сохраняет оригинальный запрос. Остальные `.pl` — явно названные контрфактические варианты.
- `-stdout.txt` и `-stderr.txt` — полный вывод соответствующего запуска. Для `unknown` сохраняются два допустимых мира. `true_model` и `false_model` относятся к полному запросу, включая его отрицание. Внутри мира `holds` перечисляет истинные атомы, остальные атомы конечного словаря ложны.

Повтор: `python3 reports/run-luna-thirty-error-probes.py` из корня репозитория. Нужен SWI-Prolog. Если полный исходный файл ещё существует в `/private/tmp`, скрипт снова проверяет его хеш; при его отсутствии сохранённые выдержки остаются доступными. Пробы используют текущий `finite-fol-meta-prover.pl`; точный хеш использованной версии записан в `results.json`.

Контрфактическое совпадение с gold показывает действие конкретных изменений внутри формальной программы. Оно не означает, что модель самостоятельно их внесёт, что все изменения семантически оправданы или что измеренная точность стала выше. Независимая CDR-проверка не выполнена.

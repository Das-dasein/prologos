## Research question

When accepted memory is already formalized correctly, does executing it with
the repository's signed-Horn checker improve a model's classification of a
difficult query over merely showing the same model the formal program?

This wave isolates reasoning and receipt use. Dialogue extraction, admission,
retrieval, next-action policy and dreams are outside this measurement. They
remain separate stages of the full agent pipeline.

## Conditions

| Condition | Model input | Measured boundary |
| --- | --- | --- |
| P0 | Natural-language rendering of the gold world | Natural reasoning baseline |
| P1 | Equivalent signed-Horn program, no execution | Effect of formal representation |
| P2 | The P1 program plus a host-generated checker receipt | Effect of execution and receipt use |

P0 and P1 have byte-identical instructions and question after replacing the
world representation. P2 receives the exact P1 prompt plus a receipt bound to
the query. The checker runs on the host; the model does not choose or operate a
tool. P2 therefore tests whether the model obeys and transmits verified output,
not autonomous tool selection.

## Fixture

The deterministic generator produces 32 cases as the Cartesian product of:

- derivation depth: 3 or 6;
- topology: chain or same-variable conjunctive join;
- raw status: `entailed`, `contradicted`, `unknown`, or `conflict`;
- replica: 1 or 2.

Unknown join cases keep all rules and split a required final gate onto another
entity. This makes variable binding, rather than keyword presence, decisive.
Every case also contains irrelevant facts. Positive and negative derivations
use separate branches, so conflict requires both complete branches.

Ground truth is recomputed by `world/checker.js` from the formal world. The
provider prompts contain neither case IDs nor evaluator labels. The compact
checked receipt exposes `raw_status`, safe status, support item IDs for the
query and its opposite, and a digest of the retained full checker evidence.

## Interpretation gates

The primary paired comparisons are P0→P1 and P1→P2, reported by depth,
topology and status. A result may support a solver increment only if P2 exceeds
P1 on the frozen fixture while every condition uses the same model, answer
envelope, one-attempt policy and retained raw evidence.

Failure to copy a correct P2 receipt is an answer-layer failure. A wrong P1
answer with a correct checker oracle is a model-reasoning failure. Neither is
an extraction failure because gold formal memory is supplied. This wave cannot
establish end-to-end memory utility or a benefit from dreams.

The sealed collector verifies the frozen fixture hash and regenerated bytes,
recomputes every checker oracle, keeps failures in the denominator, requires a
fresh output directory, permits one physical dispatch with no retry, retains
raw transport evidence, and snapshots its executable sources. The completed
Luna development result and its limits are recorded in
`reports/reasoning-stress-v1/RESULTS.md`.

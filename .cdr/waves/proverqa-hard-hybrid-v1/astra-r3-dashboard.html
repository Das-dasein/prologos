Нарушение exactly-one-call: две P2-записи исключены

Manifest задаёт для P2 ровно один закрытый вызов broker. В aggregate обе записи имеют format_valid: false, без ответа и receipt в record; ретраев не было.

После broker JSONL содержит чтение скрипта и программы, затем rg. Collector: «got 8 events».

Следствие для счёта

Это protocol-invalid, не «неправильные ответы»: ответа в aggregate нет. Поэтому P2 — 6/10, не 6/12; из hybrid исключён case 267.

Фактическое свидетельство SWI-Prolog и receipt

В 10 валидных P2 JSONL есть один command_execution lifecycle pair с закрытым query-broker.sh; завершение — exit_code: 0. Каждый проверенный скрипт принимает только ноль аргументов и запускает локальный swipl по записанному пути /opt/homebrew/Cellar/swi-prolog/10.0.2/…/swipl, записывая результат в workspace/broker-receipt.txt.

Конкретные следующие шаги

  1. Не объединять P2 с P0/P1. Сохранить candidate-run как local operational observation с разными знаменателями и двумя protocol-invalid записями.
  2. Отдельно пререгистрировать P2-multicall. Явно зафиксировать число/типы разрешённых вызовов, запрет инспекции sealed state, бюджет, invalidation и отдельный raw directory. Это не «починка» текущего one-call P2.
  3. Повторить исходный one-call протокол в свежей независимой коллекции с теми же заранее фиксированными fixture/seed, моделью, бюджетом и JSONL-аудитом; invalid записи не заменять ретраями.
  4. Добавить независимый semantic compiler check. Сверять локальную формализацию с source gold и исключать compiler-fail вместо молчаливой переметки.
  5. Вывод о сравнении — только после репликаций. Публиковать правильность, invalidation, false-positive/unknown и неопределённость; P2-hybrid оставлять отдельным subset-анализом.
